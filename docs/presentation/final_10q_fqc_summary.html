Final Presentation Q&A

FQC 수율 개선을 위한 Laminator AI 원인 후보 분석 과제

기존 공정기술 업무에 AI라는 새로운 분석 아이디어를 도입해, 반복 집계보다 수율 개선 액션 도출에 집중하도록 만드는 과제입니다.

핵심 KPI

FQC 수율, CRACK/BUBBLE Loss 감소

핵심 입력

생산/불량, BOM, Recipe, Profile, 알람

핵심 출력

HTML Report, 분석 Excel, Alert, Checklist

AI 역할

패턴 분석, 원인 후보, 액션아이템 제안

1. 현장 문제 한 문장

Laminator 공정에서 매일 발생하는 불량과 설비 이상 징후, BOM 자재 종류와 Recipe 조건 변화를 사람이 모두 즉시 분석하기 어려워 CRACK/BUBBLE 같은 주요 불량의 원인 파악이 늦어지는 문제를 해결하려고 합니다.

CRACK/BUBBLE BOM 조건 Recipe FQC 수율

2. 문제가 만드는 불편이나 손실

공정기술 담당자는 생산량, NG 수량, 불량 종류, 설비 Profile, 알람 이력, BOM 자재 조건, Recipe 조건을 수작업으로 확인해야 합니다. 이 과정이 1~2시간 이상 걸릴 수 있고, 특정 설비·시간대·자재 조건·Recipe에서 반복적으로 발생한 패턴을 놓칠 수 있습니다. 특히 히스토리가 누적되지 않으면 반복 불량이 있었음에도 근거 기반 개선 Item으로 연결되지 못합니다.

3. Before 업무 흐름

현재는 07시부터 익일 07시까지의 생산/불량 데이터를 내려받고, 엑셀에서 설비별·시간대별 NG 수량을 확인합니다. 이후 EL/AOI 이미지, 설비 알람, Profile 데이터, BOM 자재 조건, Recipe 정보를 각각 따로 확인하면서 특이점을 찾고, 수기 메모를 바탕으로 팀장 보고 자료를 작성합니다.

4. AI 개입 후 변화

AI가 생산/불량 데이터, BOM 조건, Recipe, 설비 알람, Profile 데이터를 한 번에 분석해 불량 집중 구간과 원인 후보를 자동으로 정리합니다. 예를 들어 “LAM-03 14시대 CRACK 집중이 진공도 하락, 압력 알람, 특정 Recipe 조건과 겹친다”처럼 객관적 근거를 리포트화합니다. 이 결과를 바탕으로 개인 검토나 팀 미팅에서 액션 플랜을 빠르게 도출할 수 있습니다.

AI는 설비 원인을 확정하지 않고, 근거 기반 원인 후보와 우선순위를 제안합니다. 최종 원인 확정과 조치 계획은 담당자가 승인합니다.

5. 입력 데이터 출처

입력 데이터는 라인 PC 또는 사내 시스템에서 내려받은 생산 실적 엑셀/CSV, 불량 이벤트 데이터, 설비 알람 CSV, Laminator Profile 데이터, EL/AOI 검사 결과, BOM 자재 정보, Recipe 정보, 담당자 수기 메모입니다. 원본 데이터는 외부로 반출하지 않고 로컬 또는 사내망 환경에서 처리하는 것을 전제로 합니다.

DB 활용 범위는 추가 검토가 필요합니다. 모든 설비 데이터가 MES DB에 연동되어 있지 않으므로, 파일 기반 분석을 우선 적용하고 DB 연동은 사내 보안/IT/MES 담당자와 협의하여 단계적으로 검토합니다.

6. 결과물 형태

결과물은 보고용 결과 요약 HTML 대시보드, 상세 검증용 분석 엑셀, 설비 점검·Recipe 확인·재발 모니터링 체크리스트, 그리고 반복 이슈 히스토리 기록입니다. 필요 시 특정 이상 징후가 발생했을 때 알람 시스템으로 연결하는 것도 목표입니다.

결과물 목적
HTML Dashboard팀장/현장 관리자에게 핵심 이슈와 원인 후보를 빠르게 공유
분석 Excel논문/레퍼런스 기반 근거와 원본 데이터를 상세 검증
Checklist설비 점검, Recipe 확인, 재발 모니터링 항목 관리
History Log반복 불량, 자재 조건, Recipe 조건, 액션아이템 누적

7. 성공 KPI

핵심 KPI는 단순 보고서 작성 시간이 아니라 FQC 수율 개선과 불량 Loss 감소입니다. 구체적으로는 CRACK/BUBBLE 불량 감소율, AI 액션아이템 적용 후 개선된 수율 Loss %, 동일 불량 재발 건수 감소, 원인 후보 도출 리드타임 단축, 업무 자동화로 인한 분석 시간 단축, 개선 Item 건수와 특허 아이디어 발굴 건수를 기준으로 봅니다.

8. 파일럿 제외 범위와 리스크

파일럿에서는 설비 제어값 자동 변경, 원본 이미지 딥러닝 판정, 외부 클라우드 분석은 제외합니다. 장기 목표로는 불량 발생 시 설비와 연동해 Recipe 온도나 압력 조건을 조정하는 방향도 가능하지만, 자동 제어는 Side effect가 우려되므로 파일럿에서는 의사결정 보조와 체크리스트 수준으로 제한합니다.

주요 리스크는 데이터 양식 변경, MES/DB 미연동 데이터, AI 원인 후보 과신, 자동 Recipe 변경에 따른 부작용입니다.

9. 현재 막힌 이슈와 의견 필요 지점

가장 큰 이슈는 DB를 어디까지 활용할 수 있는지 판단이 어렵고, 모든 설비 데이터가 MES에 연동되어 있지 않다는 점입니다. 또한 실제 현장 데이터의 컬럼 구조와 관리 기준이 필요합니다. 특히 공정 time, 온도, 진공도 기준값, CRACK/BUBBLE 이상 판단 기준, BOM/Recipe 조건 매핑, 재판정/재투입 이력 연결 방식은 현장 담당자와 IT/MES 담당자의 의견이 필요합니다.

10. 프로젝트 기대 효과

이 프로젝트가 잘되면 현장 관리자들은 상세한 데이터 기반 분석 결과를 모니터링하고 공유할 수 있어 불량관리 레벨이 올라갑니다. 공정기술 담당자는 반복 집계보다 원인 분석과 개선 활동에 집중할 수 있고, 팀장은 핵심 이슈와 조치 필요 사항을 빠르게 판단할 수 있습니다. 장기적으로는 엔지니어가 단순 반복 업무에서 벗어나 특허, 개선 Item, 새로운 공정 아이디어 같은 더 창의적인 업무에 도전할 수 있습니다.
