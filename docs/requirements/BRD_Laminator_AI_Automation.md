# BRD: Laminator 일일 설비/불량 현황 보고 자동화

## 1. 문서 목적

본 BRD는 Laminator 공정에서 매일 수행되는 설비/불량 현황 확인 업무를 AI로 자동화해야 하는 비즈니스 필요성과 기대효과를 정의한다.

이 문서는 제품 기능을 상세히 정의하기보다, 현재 업무의 문제, 현장 영향, KPI 연결 방식, 성공 기준, 추진 범위를 명확히 하는 것을 목적으로 한다.

## 2. 과제 개요

- 과제명: 일일 설비/불량 현황 보고서 자동 작성
- 대상 공정: MODULE-A / Laminator
- 대상 시간 기준: 07시-익일 07시
- 대상 업무: 생산량, NG 수량, 불량 종류, 불량률, 설비 Profile, 검사 NG 이미지, 시간대별 불량 집중성 확인
- 주요 사용자: 모듈공정기술 담당자, 공정팀원, 팀장
- 핵심 목표: FQC 수율 개선, CRACK/BUBBLE 불량 Loss 감소, 원인 파악 리드타임 단축, 설비/시간대별 이상 징후 조기 발견

## 3. 인터뷰 기반 현황

인터뷰 대상자는 모듈공정기술 담당자로, Laminator 공정을 담당한다. 회사 KPI 관점에서는 수율 개선, 택타임 개선, 생산성 향상, 특허 아이디어 발굴과 연결된다.

현재 업무는 매일 07시부터 익일 07시까지의 데이터를 기준으로 생산량과 불량 수량을 확인하고, EL/AOI 검사 이미지를 통해 불량 상태를 파악하는 방식으로 진행된다. 또한 설비별, 시간대별 불량 집중성, 설비 Profile 특이점, 설비 알람, 4M 관점의 원인 후보를 함께 확인해야 한다.

현장에서는 BOM 자재 종류와 Recipe 조건이 다양하게 바뀌기 때문에, 사람이 매번 평균, 표준편차, 설비/시간대별 집중성, 자재/Recipe 조건별 반복 패턴을 즉시 분석하기 어렵다. 특히 반복 이슈가 히스토리로 누적되지 않으면 같은 조건에서 반복 발생한 불량도 개선 Item으로 연결되지 못할 수 있다.

2차 인터뷰 결과, 보고서 작성 시간은 평상시 약 30분, 이슈 발생 시 약 90분으로 확인되었다. 다만 과제 성공 기준은 단순 시간 절감이 아니라 불량 감소와 원인 파악 정확도이다.

최종 추가 인터뷰에서는 우선 감소 대상 불량을 CRACK, BUBBLE 순으로 정했다. 원인 파악이 늦어질 경우 동일 불량이 재발하더라도 설비 조건, Recipe, 작업 조건이 달라져 원인을 추적하기 어려워지는 문제가 확인되었다.

추가 개선 요청에 따라 외부 태양광 모듈 Failure Mode 논문을 참고해 원인분석을 보강한다. 단순히 설비/시간대 집중만 보는 것이 아니라, EL 검사에서 확인되는 crack pattern, Bubble/Delamination의 Encapsulant/Vacuum/Temperature 연관성, Inactive area와 Flash low power의 연결 가능성을 함께 고려한다.

전문 RCA 관점에서는 원인을 바로 확정하지 않고, 1차 원인 후보와 경쟁 가설을 함께 제시한다. 예를 들어 LAM-03 14시대 CRACK 집중은 vacuum/pressure process window disturbance를 1차 후보로 두되, pre-existing micro-crack propagation, thermal gradient, 검사 편차 가능성을 함께 비교한다.

논문 참조는 단순 참고자료가 아니라 분석 품질을 높이는 업무 장치로 사용한다. 즉, 외부 PV 모듈 Failure Mode 문헌을 현장 컬럼으로 변환하여 “어떤 데이터를 더 봐야 하는지”를 제안한다. 예를 들어 CRACK은 EL pattern, inactive area, handling/stringing 이력, 라미네이션 pressure/cycle/vacuum profile을 함께 보도록 유도하고, BUBBLE은 encapsulant lot, 계면 추정 위치, 진공/온도/압력/냉각 조건을 함께 보도록 유도한다.

이를 통해 AI의 역할은 설비 문제를 단정하는 것이 아니라, 현장 담당자가 놓치기 쉬운 경쟁 가설과 검증 데이터를 빠르게 펼쳐주는 것으로 정의한다. 이 접근은 DB/MES에 모든 설비 데이터가 없더라도, 현재 확보 가능한 파일 데이터와 문헌 기반 체크리스트를 조합해 원인 파악 리드타임을 줄이는 데 목적이 있다.

## 4. 현재 업무 문제

### 4.1 수작업 집계 부담

현재는 07시-07시 기준으로 생산량, 검사량, NG 수량, 불량 종류, 불량률을 사람이 직접 확인해야 한다. 이 과정에서 데이터 소스가 여러 파일 또는 시스템으로 나뉘어 있으면 복사/붙여넣기, 필터링, 재집계가 반복된다.

### 4.2 이상 징후 발견 지연

특정 설비나 특정 시간대에 불량이 집중되는 경우, 담당자가 직접 데이터를 확인하면서 패턴을 찾아야 한다. 예를 들어 LAM-03에서 14시대 CRACK 불량이 집중되더라도, 현재 방식에서는 담당자가 직접 시간대별/설비별 데이터를 확인해야 발견할 수 있다.

### 4.3 수량 불일치 위험

재판정, 재투입, 데이터 누락 등으로 인해 생산 수량, 검사 수량, NG 수량이 맞지 않는 경우가 발생할 수 있다. 수량 불일치는 보고 신뢰성과 원인 분석 정확도에 영향을 준다.

### 4.4 설비 Profile 분석 어려움

설비 Profile 데이터는 초 단위로 기록되어 데이터 양이 많고 컬럼도 많다. 따라서 공정 time, 온도, 진공도 등 핵심 항목의 특이점을 사람이 직접 찾는 데 시간이 오래 걸린다.

### 4.5 보고 후 조치 연결 부족

보고서가 단순 현황 공유에 머무르면 실제 불량 감소로 이어지기 어렵다. 보고서에는 어떤 설비, 어떤 시간대, 어떤 불량, 어떤 Profile 변화가 연결되어 있는지 표시되어야 하며, 후속 조치 후보까지 제시되어야 한다.

### 4.6 BOM/Recipe 조건별 반복 패턴 누락

Laminator 공정은 BOM 자재 종류와 Recipe 조건이 다양하게 변경될 수 있다. 특정 자재 조건이나 Recipe 조합에서 CRACK/BUBBLE 불량이 반복되더라도, 이력이 구조화되어 있지 않으면 반복 패턴을 놓칠 수 있다.

## 5. 비즈니스 목표

본 과제의 비즈니스 목표는 다음과 같다.

1. 07시-07시 기준 NG 수량, 불량 종류, 불량률을 정확히 집계한다.
2. CRACK, BUBBLE 불량을 우선 관리 대상으로 설정하고, 설비별/시간대별 불량 집중 구간을 조기에 발견한다.
3. 공정 time, 온도, 진공도 등 Profile 이상과 불량 집중 시간의 연관성을 확인한다.
4. 설비 알람, 수량 불일치, 재판정/재투입 이력을 함께 확인한다.
5. 외부 PV 모듈 논문 기반 Failure Mode 매핑을 활용해 원인 후보의 설명력을 높인다.
6. BOM 자재 조건과 Recipe 조건별 반복 불량 히스토리를 누적한다.
7. 팀장 보고용 HTML, 분석 엑셀, 알람/체크리스트를 통해 빠른 의사결정을 지원한다.
8. 최종적으로 FQC 수율 개선, 불량 Loss 감소, 원인 파악 리드타임 단축에 기여한다.

## 8. KPI 및 성과 측정

본 과제는 보고서 작성 시간 절감보다 불량 감소와 원인 파악 성과를 중심으로 측정한다.

### 8.1 정량 KPI

- 주요 불량 감소 건수 또는 감소율
- CRACK, BUBBLE 불량 감소율
- AI 액션아이템 적용 후 개선된 수율 Loss %
- 동일 불량 재발 건수 감소
- 원인 후보 도출 리드타임 단축
- 문헌 기반 RCA 근거가 포함된 원인 후보 비율
- 1차 후보 대비 경쟁 가설 검토 완료율
- 설비/시간대별 이상 징후 탐지 건수
- 생산/검사/NG 수량 불일치 탐지 건수
- 팀장 보고 후 후속 조치 연결 건수
- 개선 Item 및 특허 아이디어 발굴 건수

### 8.2 품질 KPI

- 보고 누락 감소
- 불량 집중 구간 조기 발견률
- Profile 이상과 불량 집중 간 연관성 발견률
- 원인 후보의 현장 검증 적합도
- 공정팀 의사결정 속도 향상

### 8.3 참고 KPI

- 평상시 보고서 작성 시간: 약 30분
- 이슈 발생 시 보고서 작성 시간: 약 90분
- 시간 절감은 보조 지표로 활용하고, 핵심 성과 지표는 불량 감소와 원인 파악으로 설정한다.

## 9. 이상 징후 판단 방향

본 과제에서 이상 징후는 단일 데이터만으로 판단하지 않고, 설비 집중, 시간 집중, 불량 코드 집중, Profile 이상, 설비 알람, 수량 불일치를 함께 본다.

제안 기준은 다음과 같다.

- 동일 설비에서 동일 불량이 1시간 내 5건 이상 발생
- 특정 설비의 시간당 불량률이 전체 평균의 2배 이상 증가
- 특정 시간대 NG 수량이 직전 3시간 평균 대비 3배 이상 증가
- 특정 불량 코드가 일일 전체 NG의 40% 이상 차지
- 설비 알람 발생 전후 30분 이내 동일 불량 연속 발생
- 공정 time, 온도, 진공도 이상이 NG 집중 시간과 겹침
- 재판정/재투입 이력과 수량 불일치가 동시에 발생

## 10. 보안 및 운영 조건

- 원본 설비 데이터는 외부로 반출하지 않는다.
- 자동화 도구는 로컬 PC, 라인 PC 또는 사내망 환경에서 실행하는 것을 원칙으로 한다.
- 과제 제출 및 테스트에는 비식별 샘플 데이터만 사용한다.
- 제품 코드, 고객 정보, 세부 Recipe, 원본 이미지 등 민감 정보는 공유하지 않는다.
- AI 결과는 담당자가 검증한 뒤 보고 자료로 사용한다.
- 사람이 최종 승인해야 하는 항목은 원인 후보 확정, 설비 점검/Recipe 확인 등 조치 계획, 팀장 보고 전 최종 문구이다.

## 11. 주요 리스크

| 리스크 | 영향 | 대응 방향 |
|---|---|---|
| 데이터 양식 변경 | 자동 집계 오류 | 컬럼 매핑 검증 단계 추가 |
| 재판정/재투입 데이터 누락 | 수량 불일치 오판 | 검증 화면에 이력 확인 항목 표시 |
| 이상 기준 과다 탐지 | 알람 피로도 증가 | P1/P2/P3 우선순위 표시 |
| AI 원인 후보 과신 | 잘못된 조치 가능 | 원인 후보는 확정이 아닌 검토 대상으로 표시 |
| 보안 제약 | 데이터 활용 제한 | 로컬/비식별 처리 원칙 적용 |
| MES/DB 미연동 데이터 | AI 분석 범위 제한 | 파일 기반 분석을 우선 적용하고 DB 연동은 사내 IT/MES 협의 후 단계 적용 |
| 자동 Recipe 변경 | 설비 Side effect 가능 | 파일럿에서는 자동 제어 제외, 담당자 승인 기반 조치로 제한 |

## 12. 성공 기준

본 과제는 다음 조건을 만족할 때 성공으로 판단한다.

1. 07시-07시 기준 NG 수량, 불량 종류, 불량률이 정확히 집계된다.
2. 설비별/시간대별 불량 집중 이슈를 자동 탐지한다.
3. 공정 time, 온도, 진공도 이상과 불량 집중 시간의 연관성을 표시한다.
4. 수량 불일치, 재판정, 재투입 이력을 검증 항목으로 보여준다.
5. BOM/Recipe 조건별 반복 불량 히스토리를 기록한다.
6. 팀장 보고용 HTML, 분석 엑셀, 알람/체크리스트를 출력한다.
7. 자동화 결과가 CRACK, BUBBLE 불량 감소 또는 원인 파악에 기여한다.
8. 보고 후 설비 점검, Recipe 확인, 동일 불량 재발 모니터링으로 이어진다.
